## What and why

`CLAUDE.md` grew 26KB → 161KB in two months and is loaded in full at the
start of every session — roughly 40k tokens before a word is typed. The
size is the symptom; the cause is that **it was the only file in the system
with no eviction rule.** `BACKLOG.md` removes fixed items. `ATOMIC_TASKS.md`
says in its own header to delete finished sections. `docs/` is additive by
design. `CLAUDE.md` was declared "the current-state record" but implemented
as append, so it accumulated the entire past at the resolution of the
present.

What the audit found, measured rather than asserted:

- **62% of the file** (99,784 bytes, 1,530 lines) was one section: 44 dated
  session writeups spanning 2026-09-06 → 2026-11-01.
- **Seven supersession chains, 36,412 bytes across 24 of the 44 entries.**
  Markdown preview scroll-sync alone is 4 entries and 7,643 bytes
  (added → jumpy → choppy → wrong pace), where the surviving truth is one
  sentence — and you have to read all four *in order* to know which it is.
- **Every externalisation so far was additive; nothing ever left.**
  `docs/concepts/` holds 13,268 bytes of principles, and `CLAUDE.md` still
  restated all seven inline while linking to exactly one of them, once.
  `docs/packages/` holds 88,496 bytes; the Architecture section still held
  25,168 bytes of the same material.
- **The same session was narrated twice**, in `CLAUDE.md` and
  `ATOMIC_TASKS.md`, with **2 literally shared sentences** between them —
  not copy-paste, the same events re-told in different words.
- **One lesson recorded 7 times** (reentrant locking), "confirmed against
  real vim" 18 times. Rules were being stored as anecdotes because there
  was no table for a rule.
- **528KB of prose against 802KB of Go.**
- It had already misled a reader, and the file said so itself: *"confirmed
  by a verification fork rather than trusting this file's own prose, which
  read as if both frontends already had it."* That's the real cost — not
  tokens, trust.

## Shape

Content sorts by **lifetime**, not by topic, and each lifetime gets a file
with one write rule:

| lifetime | file | write rule |
|---|---|---|
| indefinite, about us | `CLAUDE.md` | rewritten |
| derivable from code | `ARCHITECTURE.md` | regenerated |
| until it's picked up | `ROADMAP.md` | head shrinks, middle reorders, far end grows |
| until the work ends | `handovers/<ID>.md` | overwritten, then frozen |
| permanent, chronological | `LOG.md` · `DECISIONS.md` · `GOTCHAS.md` | append-only |

The relational part: log → handover (total); decision → handover or null;
decision → gotcha or null; everything keyed on one ID space where an ID is
minted at handover size and never renamed.

Two properties make it survivable without a tool to enforce it:

- **Prose lives in exactly one table — handovers.** Everything else points.
  A second narrator rebuilds the 528KB.
- **All pointers go backwards in time.** A new row may name an old ID; an
  old row never needs editing to name a new one. That keeps a close at two
  writes instead of five, which is the difference between a system that
  survives a bad week and one that doesn't.

## Tried and dropped

- **Move the 99KB to `HISTORY.md` and be done.** Rejected: it fixes the
  symptom for about six weeks and then recreates the identical file
  somewhere else, because the mechanism that produced it — append, no
  eviction — is untouched.
- **A separate narrative "process" document.** Rejected as denormalisation:
  decisions in order, plus the handovers they point at, *are* the process.
  Writing it separately is a third telling of events already told twice.
- **`parked` as a handover status.** Rejected in favour of the better
  shape: parked work closes as done and returns to the roadmap. That
  *removes* a state rather than adding one, so the open set can never
  accumulate corpses.
- **Scope-tagging gotchas by package.** Rejected: the reentrant-lock gotcha
  was found in `editor` and has since bitten `piecetable`,
  `clipboard-register` and `tui-base`. Tagged by package it would have
  been invisible for all three. Tag by *trigger shape* instead, and bias
  wide — a false positive costs a few seconds of reading; a false negative
  costs the bug again.
- **Backfilling 44 historical handovers.** Rejected (D57): their decisions
  and gotchas are extracted; the narrative stays frozen in `archive/`.
