## What and why

A release pipeline has existed since 2026-10-31 and has never run a test.
`vet` and `test` were run by hand, which is fine while one person is the
only one merging and worthless the moment that isn't true.

T70 is what made this worth doing now rather than later: with both
frontends driving real frames headlessly, a push can actually verify the
thing that used to need a human with a terminal. The e2e harnesses are
primarily a development tool — their point in CI is safeguarding merges.

## Shape

One job, `ubuntu-latest`, on pushes to `main` and on every pull request:
gofmt → vet → build → test → test -race → tagged builds → record check.

Three things that aren't obvious:

- **Gio's cgo dependencies are needed to *test*, not just to release.**
  `go test ./...` compiles `internal/frontend/gui-base`, which imports Gio,
  whose Linux build is cgo and links against Wayland/X11/Vulkan dev headers
  (G23). A bare runner has none of them (G24). Same apt list as
  `release.yml`.
- **The tagged build is its own failure surface.** A bare `go build ./...`
  links gotreesitter's full grammar fleet, so a break specific to the
  curated subset only appears under `GRAMMAR_TAGS` — previously first seen
  when cutting a release.
- **`-timeout` on each test command, plus `timeout-minutes` on the job.**
  Not boilerplate: G34's deadlock hangs the process rather than failing it,
  and the Go timeout is what produces the goroutine dump that identified
  it. The job timeout is the outer stop.

`LSPMANAGER_INTEGRATION` is deliberately unset — those tests download real
toolchains and talk to the live mason registry, so they stay a manual
check rather than something every push pays for and every network blip
fails.

## The bug this found

Wiring `docs-check.sh` in as a gate meant testing that it can fail. Four of
its seven checks could not: they reported through `note()` from inside a
`cmd | while read` pipeline, which runs in a subshell, so the `fail=1` was
discarded. The script printed `broken link in ROADMAP.md -> handovers/TNNN.md`
and then `record check: clean`, exit 0, in the same run. Sections 3, 4, 5
and 7 had been decorative since they were written.

Fixed with process substitution, and each of the four then confirmed to
fail on purpose-built bad input: a broken relative link, a malformed ID
span, a row count in prose, and a Go comment citing an archived doc. → G37

## Tried and dropped

- **A lint job alongside the test job.** Nothing beyond `vet`/`gofmt` is
  configured in this repo, so it would have been an empty step with a name.
- **Running the LSP integration suite on a schedule.** Real, but it's a
  separate decision about what a flaky external dependency is allowed to
  do to a build, and it doesn't belong inside the change that introduces
  the first test gate.
