## What and why

Found live 2026-10-31 during preview testing: `<C-d>`/`<C-u>` weren't bound
at all. Flagged then as *not* a drop-in like T33's other bare keys, because
real vim moves the cursor along with the scroll and needs the current
viewport height — information `Editor` and `keyengine` didn't carry.

## Real vim behaviour — verified, not inferred (G19)

Measured against real `nvim`, in a **real 24-row terminal** rather than
headless, because the window-relative half is exactly what G33 says
headless gets wrong:

| probe | result |
|---|---|
| `gg` then `<C-d>` (22 text rows) | cursor 1 → **12**, `top` 1 → **12** |
| plain `11j` for contrast | cursor 1 → **12**, `top` stays **1** |
| second `<C-d>` | cursor/top → **23** |
| `<C-u>` | back to **12** |
| `2<C-d>` | cursor → **3**, and `scroll` is rewritten to **2** |
| plain `<C-d>` after that | → **5** — the count persisted |
| column on ragged lines | preserved |
| at EOF | clamps to the last line |

The first two rows are the finding this task turned on, and they contradict
what this handover previously claimed (see Corrections).

## Shape, as built

**Editor owns the viewport** (D64). Frontends report two primitives per
render — available vertical space and line height — and render where
they're told:

```
SetViewportMetrics(verticalSpace, lineHeight)  ->  rows = space / lineHeight
Viewport()  ->  the slice to draw      ViewportTopRow()  ->  where it starts
```

so zoom, resize and font changes all fall out of one division, and a
terminal's one-cell line height degenerates correctly rather than needing a
special case. `Viewport(topRow, visibleRows, margin)` lost all three
parameters because Editor already knows them.

`<C-d>` resolves to **two actions, not one** (D68):

```go
resolveHalfPage: []Action{ move, ScrollToAction{Row: view.TopRow + distance*dir} }
```

`MoveAction` is `resolveLineStep` unchanged — it already walks N rows,
preserves the column and clamps at both ends, so the cursor half of `<C-d>`
really is `Nj` with a computed N. The new half is `types.ActionScrollTo` →
`Editor.SetViewportTop`, which clamps and then re-follows, so an explicit
scroll can never strand the cursor off screen.

Cursor-follow became **one policy, minimal scroll** (D69), living on
`Cursor.Update` rather than `SetViewportMetrics` — the window has to be
re-followed when the *cursor* moves, not only when the frontend reports new
metrics. The first version followed only on metrics and shipped a stale
`topRow` between renders; a test caught it, not the eye.

`keyengine` took table data only: `<C-d>`/`<C-u>` as Directs → `{Verb:
Move, Noun: HalfPageDown/HalfPageUp}`, in both normal and visual tables.
No dispatch-logic change — the "simple, not easy" test held again.

## Corrections to this handover's own earlier claims

1. **"The scrolling half needs no implementation."** Wrong, and it was the
   load-bearing claim. Cursor-follow only guarantees the cursor stays
   *visible*; vim moves the window by the same half-page regardless, so the
   cursor keeps its screen row. Caught by testing against real nvim, not by
   review. → D68
2. **"`tui-base` keeps `ScrollTo(cursorRow - cursorTopPadding)`."** It gave
   up pin-at-N for minimal scroll. `cursorTopPadding` survives only in the
   markdown preview, where it isn't a cursor-follow at all. → D69

## Found along the way

- **`<C-v>` was unreachable in the real application.** Bound in `keyengine`
  since block-visual shipped (T54), but neither frontend ever translated
  the key — every unit test passed while the mode could not be entered by a
  user. Fixed in both frontends; `TestE2EBlockVisualIsReachable` guards it.
  This is the gap class an e2e harness exists for, and the clearest
  argument yet for extending it.
- **G34** — tview holds the app lock across `SetAfterDrawFunc`, so
  re-entering tview from a draw hook deadlocks. Hit for real: a pane-resize
  re-render reached `Application.SetFocus` four calls down and hung the
  process for a full 10-minute test timeout.
- **G35** — tcell's `GetContents` returns the live backing array, not a
  copy; reading it from a test goroutine races the draw. The per-cell
  accessor is *not* the fix — it reads a buffer that is torn mid-draw and
  reads as blank, which silently satisfies "this text is gone" assertions.
- **G36** — `git checkout <file>` to undo a deliberate test-break destroyed
  a file of uncommitted work, recovered from the session transcript.
